# 從網頁到知識庫：桃園市觀音區

本專案提供一個四人共用的爬蟲公版。每位組員在自己的 Git 分支執行程式，程式不讀取 `urls.csv`。使用者主要只需要貼上網址，編號、網站類型、負責組員和探索深度會自動處理；只有延伸頁面才需要補父頁面 id。

## 安裝

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 使用方式

### 互動模式

```bash
python crawler/crawler.py
```

程式啟動後會先詢問組員編號，接著逐筆詢問：

1. 組員編號：輸入 `A`、`B`、`C` 或 `D`。
2. 網址。
3. 來源種類：原始網址、網頁內延伸、組員額外查詢。
4. 若為網頁內延伸，輸入父頁面 id。
5. 備註，可直接按 Enter 略過。

網站類型會由網址自動判斷，編號會依剛才輸入的組員代號自動產生，例如 `A-001`、`A-002`。輸入 `quit` 可結束新增網址。程式只會處理這次輸入的網址，不會自動讀取專案內的網址清單。若使用預設輸出位置，資料會自動放入 `output/A`、`output/B`、`output/C` 或 `output/D`。

### 單筆命令列模式

也可以用參數輸入一筆來源，適合組員在自己的腳本或批次流程中呼叫：

```bash
python crawler/crawler.py \
  --url "https://example.org/related" \
  --source-kind internal \
  --parent-id page_001 \
  --notes "與觀音區歷史沿革相關" \
  --output output/A
```

YouTube 範例：

```bash
python crawler/crawler.py --url "https://youtu.be/example" --source-kind extra
```

## `urls.csv` 登記格式

這個檔案只是登記表，爬蟲不會讀取它。Git 合併前，各組員把自己新增的網址補回這個檔案，方便最後驗收：

```csv
id,type,source_url,source_kind,parent_id,depth,assigned_member,notes
page_032,web,https://example.org/related,internal,page_001,1,A,與觀音區歷史沿革相關
page_033,web,https://example.org/new-source,extra,,0,C,由關鍵字「觀音 白沙岬燈塔 官方」找到
```

欄位規則：

- `seed`：老師提供的起始網址。
- `internal`：從某個來源頁面內找到的相關延伸頁面，必須填 `parent_id`。
- `extra`：組員自行檢索找到的網站，必須記錄查詢關鍵字或加入理由。
- `depth`：本專案原則上只做一層延伸，除非組內另行同意。
- 每個網址的 `id` 必須唯一，新增前先檢查是否重複。

## 四人分工

### A：維基百科、歷史地理與文化知識

主要來源：`page_001`、`page_010`、`page_015`、`page_016`、`page_020`、`page_028`、`page_031`。

工作內容：整理維基與文化資料、找出歷史地理敘述、處理相關內部文章，並完成至少 3 筆官方或正式出版品交叉查核。建議關鍵字包括「觀音區歷史沿革」、「石觀音」、「觀音區河川」、「大潭發電廠」。

### B：YouTube、字幕與代表性畫面

主要來源：`page_005`、`page_011`、`page_018`、`page_019`、`page_026`、`page_027`、`page_030`。

工作內容：取得影片標題、頻道、公開 metadata、合法字幕與 3–5 張代表畫面。每張畫面要有時間點和描述。影片沒有字幕或受到平台限制時，記錄原因，不自行猜測字幕內容。

### C：官方、政府與機構網站

主要來源：`page_002`、`page_006`、`page_007`、`page_008`、`page_012`、`page_013`、`page_024`。

工作內容：整理官方頁面、圖片與地方產業資料，優先尋找桃園市政府、中央機關、政府資料庫與官方出版品作為查核來源。建議關鍵字包括「白沙岬燈塔 航港局」、「觀新藻礁 保護區」、「觀音蓮花 農業部」、「觀音工業區 經濟部」。

### D：新聞、部落格、旅遊與飲食媒體

主要來源：`page_003`、`page_004`、`page_009`、`page_014`、`page_017`、`page_021`、`page_022`、`page_023`、`page_025`、`page_029`。

工作內容：清理長篇文章、篩選文章圖片、比對不同媒體的重複敘述，並把媒體內容與官方查核資料分開標示。作者、日期、原始網址與圖片來源都要保留。

各組可自行新增網站，但新增來源必須標記 `source_kind=extra`，先確認與觀音區相關、沒有和既有網址重複，再加入 `urls.csv`。

## 建議工作流程

1. 從目前版本建立自己的 Git 分支，例如 `member-A`。
2. 執行 `python crawler/crawler.py`，手動輸入自己的組員編號。
3. 每次只貼上自己負責的網址；程式會自動產生 `A-001`、`A-002` 等編號。
4. 需要處理不同網站時，複製公版成自己的 `crawler_member_A.py`，只修改自己負責的網站規則。
5. 將程式、輸出資料與網址登記表一起 commit，再用 Git 合併四組成果。

程式會依組員編號自動使用 `output/A`、`output/B`、`output/C` 或 `output/D` 資料夾，避免圖片和文章檔名互相覆蓋。

## 重複執行與資料保存

程式每次執行後會讀取目前輸出資料夾中的 `index.jsonl`，再依 `id` 合併本次結果：

- 本次 `id` 和舊資料相同：用本次新資料取代舊資料，原本在檔案中的位置保留。
- 本次 `id` 是新的：保留舊資料，將新資料加在檔案下面。
- `crawl_report.csv` 和 `index.jsonl` 使用完全相同的合併結果。
- `summary.json` 會記錄本次新增筆數、取代筆數，以及合併後的總筆數。

因此組員可以一次爬一個網址，之後再繼續執行，不需要手動複製或合併報告。相同編號適合用來重新爬取或修正同一筆資料；如果是不同來源，請使用新的編號。

文章與圖片檔案會依來源 id 保存。相同 id 重新爬取時，新的文章會覆蓋同名文章；舊圖片檔案不會自動刪除，避免誤刪仍被其他資料引用的檔案。

## 各組修改自己的爬蟲

不同網站的 HTML 結構可能不同。每位組員可以複製 `crawler/crawler.py`，另存為自己的檔案，例如 `crawler_member_A.py`，再依分配到的網站修改：

- `NOISE_SELECTORS`：網站專用的廣告、導覽、推薦內容選擇器。
- `extract_content()`：網站的正文容器、標題、作者與日期欄位。
- `related_links()`：只保留正文內與觀音區相關的連結，排除選單與推薦區。
- `image_candidates()`：網站的 lazy loading 欄位，例如 `data-src`、`data-original` 或自訂屬性。
- `crawl_youtube()`：字幕來源與影片 metadata；只能處理合法可取得的資料。

修改時請保留相同的輸出欄位，讓四組成果可以合併。每個組員的客製化程式要在檔案開頭註明適用網站與修改原因。

## 輸出欄位與成果

- `output/<組員>/index.jsonl`：每個輸入來源一筆 JSON，包含 id、網址、來源類型、父頁面、負責組員、標題、正文、圖片、連結、關鍵字、爬取狀態與失敗原因。
- `output/<組員>/crawl_report.csv`：逐網址驗收紀錄。
- `output/<組員>/articles/`：清理後的 Markdown 文章。
- `output/<組員>/images/`：去重後的文章圖片。
- `output/<組員>/videos/`：影片相關畫面或字幕整理檔案。

爬蟲會尊重 robots.txt、限速與網站存取限制。不得繞過登入、付費牆、驗證碼或平台下載限制。沒有取得的正文、字幕、圖片或畫面必須記錄原因，不用其他資料替代。

## 組員注意事項

1. 每個來源都要留下原始網址與取得時間。
2. 網頁內延伸連結只收與觀音區主題直接相關的頁面，最多一層。
3. 不要把導覽列、登入頁、編輯頁、網站地圖、廣告和推薦文章當成正文來源。
4. 圖片要保存原始網址、所屬文章和說明；Logo、Banner、追蹤像素與社群按鈕要排除。
5. 維基、新聞、部落格和旅遊網站是參考起點，不能直接當成權威文獻。
6. 每組至少整理 3–5 個關鍵字，並把原始敘述與查核結果分開保存。
7. 執行失敗或網站無法存取時，保留錯誤訊息，不要刪除該筆來源。
